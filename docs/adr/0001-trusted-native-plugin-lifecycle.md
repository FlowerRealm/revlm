# 使用受信任的原生插件并以文件系统作为安装真相

状态：accepted

Revlm 将用户安装插件视为完全信任的原生代码，不提供安全边界、插件依赖、多版本并存或回滚。插件以稳定 ID 唯一安装，版本号只保留为清单元数据；更新直接替换同一插件目录。这样避免了安装状态表和版本选择器。

## 后续修订

两处已被后续决定取代，其余仍然有效。

**启用状态的载体。** 原文说“启用状态由文件系统标记表达”。启用状态现在保存在核心配置的禁用清单中（参考 realagent 的同名做法），不使用文件系统标记。文件系统仍然是**已安装包**的唯一真相，但不是**启用意图**的载体。这样 `active/` 符号链接与 `disabled/` 标记两套目录一并取消，与原文反对“重复状态”的理由一致。

**变更的生效时机。** 原文说“所有变更都等外部机制触发冷启动后生效”。[ADR 0007](0007-registry-replaces-symbol-interposition.md) 之后，启用与禁用即时作用于注册表，因此路由和模型目录立即变化；数据库迁移仍然只在冷启动执行。原文反对的“热加载状态机”指的是在运行中替换已加载代码，注册表的登记与注销不属于此列。

原文“保留 C++/hpp 的直接扩展能力”一句所指的符号覆盖模型已由 ADR 0007 取消，扩展改为显式注册。

## 考虑过的方案

- 沙箱、签名、能力声明：与“安装即完全信任”前提冲突。
- 多版本目录、回滚和 active 符号链接：制造重复状态，且产品明确不需要。
- Revlm 自行重启或热加载：Revlm 没有自重启能力，热加载还会制造 worker 状态不一致。
