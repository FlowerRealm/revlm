# 生命周期符号由 bootstrap 显式 dlopen 调用，不走符号插桩链

状态：accepted，前提已由 [ADR 0007](0007-registry-replaces-symbol-interposition.md) 推广

> **背景变化。** 本 ADR 写作时，数据面仍计划使用 `LD_PRELOAD` 符号插桩，本文的结论是把生命周期符号排除在那个模型之外。ADR 0007 随后用同一组理由取消了整个 `LD_PRELOAD` 方案，因此“显式加载后调用”现在是所有插件接口的统一方式，不再是生命周期专属的例外。本文的论证保留，因为它是 0007 的直接依据。
>
> 一项代价已经消失：不再有 bootstrap 与 worker 两个进程，插件的静态初始化只执行一次，下文“代价”一节所述的幂等约束不再适用。

插件的生命周期入口 `revlm_plugin_migrate()` 与 `revlm_plugin_cleanup()` 不通过符号插桩解析。宿主对每个目标插件单独执行 `dlopen(RTLD_NOW | RTLD_LOCAL)`，用 `dlsym` 取出该插件自己的符号并调用，随后进入下一个插件。

## 理由

生命周期符号如果沿用同名符号链，会引入三个数据面不存在的问题。

一是静默失效。链上任何一个插件忘记通过 `RTLD_NEXT` 转发，其后所有插件的迁移都不会执行。数据面 hook 忘记转发会立即表现为请求失败，而迁移缺失只在若干天后以“表不存在”的形式暴露。

二是失败无法归因。一条链只产生一次调用，抛出的异常无法对应到具体插件，而宿主需要把 `failed` 状态和错误信息记录到单个插件上。

三是事务粒度无法满足。链是一次调用，只能包在一个事务里，任一插件失败会回滚其他插件已完成的迁移，与“每次插件迁移在单个数据库事务中执行、失败只回滚本次迁移”相矛盾。

显式 `dlopen` 同时解决了两个调用时机问题：禁用插件不在 `LD_PRELOAD` 中但仍可被单独加载，待卸载插件按定义不属于启用集合，只有显式加载才能调用它的 `revlm_plugin_cleanup()`。`RTLD_LOCAL` 保证被加载插件的符号不进入全局命名空间，因此对某个插件调用生命周期符号不会命中另一个插件的同名实现。

## 代价

插件的静态初始化器会在 bootstrap 进程中执行一次，`execv` 之后在 worker 进程中再次执行。插件作者必须保证静态初始化是幂等的，不在其中建立连接、写文件或注册全局状态。这条约束写入插件包格式文档。

## 考虑过的方案

- 在 worker 中于核心 schema 完成后调用 `revlm_plugin_migrate()`：符号来自 `LD_PRELOAD`，退化为上述符号链模型，且无法覆盖待卸载插件的 cleanup。
- 由宿主维护插件生命周期函数表：与“插件是核心 hpp 的 cpp 实现、宿主不维护插件对象注册表”的前提冲突。
