# 用启动期注册表取代符号插桩链

状态：accepted，取代 [ADR 0003](0003-api-key-owned-protocol-dispatch.md) 的分发结论

Revlm 不再使用 `LD_PRELOAD` 加载插件，也不再通过同名符号和 `RTLD_NEXT` 链分发协议请求。宿主用 `dlopen(RTLD_NOW | RTLD_LOCAL)` 加载每个启用插件，调用它的注册入口，插件把自己的数据面路由、模型目录和普通全局端点登记到核心注册表。路由表的键是方法、路径和 `ChannelGroup.type` 的组合。一次请求经过 API key 鉴权得到 ChannelGroup 之后，核心用这三者查表，调用唯一命中的协议处理器。

## 理由

ADR 0003 的硬约束一节已经指出，共享的 `httplib::Server` 无法按 API key 在同一路径的多个 handler 之间选择，并写明“若要求只有目标插件被调用，就必须另建启动期函数表”。当时否决函数表的理由不是它不管用，而是它“不再是单纯的 hpp/cpp 覆盖模型”。这条纯洁性约束现在被放弃，因为维持它的代价高于它的收益。

ADR 0006 已经论证过符号链的三个缺陷：链上任何一个插件忘记转发会让其后所有插件静默失效；一条链只产生一次调用，失败无法归因到具体插件；粒度只能覆盖整条链。这三条对数据面同样成立，而且数据面每个请求都要走一次，暴露面远大于每天执行一次的生命周期。

注册表还把 ADR 0003 只能回避的冲突变成可支持的场景。两个插件为不同的 `ChannelGroup.type` 服务同一路径时，表用三元组区分，两者都能工作；两个插件登记完全相同的键时，宿主在注册阶段直接报错，而不是按加载顺序静默取舍。

路径由插件在注册时提供，核心不预置任何前缀。这让路径形状与 OpenAI 不同的协议无需改动核心即可接入。

现有插件实现的四个扩展点——模型目录、上游构造、上游重试和端点注册——没有一个是在覆盖核心已有实现，全部是“核心声明、插件填空”。符号插桩提供的覆盖能力没有被使用，而它带来的静默失效模式是真实的。

## 代价

插件不再能覆盖核心已实现的函数。将来若需要改变核心某个已有行为，必须显式增加扩展点。这是有意的取舍：扩展点是可枚举、可审计的契约，符号覆盖是隐式的。

主程序必须以 `ENABLE_EXPORTS`（`-rdynamic`）构建，否则 `dlopen` 载入的插件无法解析核心符号。

## 连带结论

不再需要 `LD_PRELOAD`，因此不再需要“bootstrap 进程拼装预加载环境后 execv worker”的双进程结构。加载、迁移与服务在同一个进程内完成，插件状态和错误信息保存在进程内数据结构中，不需要跨进程序列化文件或环境变量。加载顺序规则、`RTLD_NEXT` 转发样板、插件之间的符号可见性冲突和静态初始化被执行两次的约束一并消失。

## 考虑过的方案

- 维持 ADR 0003 的符号链：保留了 hpp/cpp 覆盖模型的纯洁性，但代价是每请求一次的转发链、三种静默失效模式，以及核心必须硬编码 `/v1` 前缀。
- 核心注册全局 catch-all 后按前缀判断：与控制台自身的端点冲突，且核心仍需知道哪些前缀属于数据面。
- 由插件清单声明数据面前缀：比 catch-all 好，但注册表已经把路径带进来了，清单再声明一次是重复信息。
